# IN Operator

## Overview

The `IN` operator checks whether a value matches any value in a list.

It is commonly used to replace multiple `OR` conditions, resulting in cleaner and more maintainable SQL.

Examples:

- Employees from specific departments
- Customers from selected cities
- Products in selected categories
- Orders with specific statuses

---

# Learning Objectives

After completing this chapter, you will be able to:

- Use the IN operator.
- Replace multiple OR conditions.
- Use NOT IN.
- Use IN with subqueries.
- Follow best practices.

---

# Syntax

```sql
SELECT column_name
FROM table_name
WHERE column_name IN (value1, value2, value3);
```

---

# Basic Example

Display customers from Delhi, Mumbai, or Pune.

```sql
SELECT
    first_name,
    city
FROM sales.customers
WHERE city IN ('Delhi', 'Mumbai', 'Pune');
```

Example Output

| first_name | city |
|------------|------|
|Arjun|Delhi|
|Sneha|Mumbai|
|Pooja|Pune|

---

# Equivalent OR Query

```sql
SELECT
    first_name,
    city
FROM sales.customers
WHERE city = 'Delhi'
OR city = 'Mumbai'
OR city = 'Pune';
```

Both queries return the same result.

---

# Numeric Example

Display employees from departments 2 and 4.

```sql
SELECT
    first_name,
    department_id
FROM hr.employees
WHERE department_id IN (2, 4);
```

---

# Product Example

Display products with IDs 1, 3, and 5.

```sql
SELECT
    product_name
FROM inventory.products
WHERE product_id IN (1, 3, 5);
```

---

# Using NOT IN

Display customers who are not from Delhi or Mumbai.

```sql
SELECT
    first_name,
    city
FROM sales.customers
WHERE city NOT IN ('Delhi', 'Mumbai');
```

---

# Combining IN with ORDER BY

```sql
SELECT
    first_name,
    city
FROM sales.customers
WHERE city IN ('Delhi', 'Mumbai', 'Pune')
ORDER BY city;
```

---

# Combining IN with AND

Display IT and Finance employees earning more than 60,000.

```sql
SELECT
    first_name,
    salary,
    department_id
FROM hr.employees
WHERE department_id IN (2, 4)
AND salary > 60000;
```

---

# IN with a Subquery

The `IN` operator can compare against the results of another query.

Display employees who belong to departments located in Hyderabad.

```sql
SELECT
    first_name,
    department_id
FROM hr.employees
WHERE department_id IN
(
    SELECT department_id
    FROM hr.departments
    WHERE location = 'Hyderabad'
);
```

The subquery runs first and returns matching department IDs.

# Best Practices

- Use `IN` instead of long `OR` chains.
- Keep value lists organized.
- Use subqueries when the values come from another table.
- Prefer joins over large subqueries when appropriate (covered later).

---

# Common Mistakes

## Missing Parentheses

❌ Wrong

```sql
WHERE city IN 'Delhi', 'Mumbai';
```

✅ Correct

```sql
WHERE city IN ('Delhi', 'Mumbai');
```

---

## Mixing Data Types

❌

```sql
WHERE department_id IN ('1', '2');
```

✅

```sql
WHERE department_id IN (1, 2);
```

Use values that match the column's data type.

---

## NOT IN with NULL Values

Be careful when the list or subquery can contain `NULL`.

Example:

```sql
WHERE department_id NOT IN
(
    SELECT department_id
    FROM hr.employees
);
```

If the subquery returns a `NULL`, the result may not be what you expect.

For these situations, `NOT EXISTS` is often the better choice. You'll learn this later in the course.

---

# Performance Tip

For a small list of values, `IN` performs similarly to multiple `OR` conditions.

When using a subquery, PostgreSQL's optimizer may internally transform the query into a more efficient execution plan.

Always use `EXPLAIN` for performance analysis on large datasets.

# Interview Questions

### What is the purpose of the IN operator?

It checks whether a value exists in a specified list or subquery result.

---

### Is IN the same as multiple OR conditions?

Yes.

For many cases, they produce equivalent results, but `IN` is usually easier to read.

---

### What is the opposite of IN?

```sql
NOT IN
```

---

### Can IN use a subquery?

Yes.

The list of values can come from another query.

# Cheat Sheet

| Statement | Purpose |
|-----------|---------|
| `IN (...)` | Match any value in a list |
| `NOT IN (...)` | Exclude values in a list |
| `IN (SELECT ...)` | Compare with subquery results |

# When NOT to Use IN

Avoid very large hard-coded lists such as:

```sql
WHERE customer_id IN
(
    1,2,3,4,5,...,5000
);
```

For large sets of values:

- Store them in a table.
- Use a temporary table.
- Join with another table.
- Use a subquery.

These approaches are more maintainable and often perform better.

---

# Summary

The `IN` operator simplifies filtering when multiple values are acceptable. It improves readability, reduces repetitive `OR` conditions, and works with both fixed value lists and subqueries, making it one of the most commonly used SQL filtering techniques.
